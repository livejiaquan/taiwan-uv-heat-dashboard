# 使用者研究：誰會用這個網站

本文件從需求分析的角度整理使用者、情境、任務與非功能需求，作為介面取捨的依據。沒有做真人訪談；persona 是依產品定位、資料特性與同類產品的使用模式推論而來，上線後應以實際使用紀錄修正。

## Persona

### 1. 通勤上班族・阿哲（32 歲，臺北）
- **情境**：早上出門前或午休前，站在門口或電梯裡用手機看一眼。
- **想知道**：「中午出去買便當要不要撐傘？」「下班時還熱不熱？」
- **限制**：單手操作、只有 5–10 秒的注意力、可能在戶外強光下看螢幕。
- **成功標準**：打開頁面不用捲動，就看到結論與幾點到幾點要防曬。

### 2. 照顧者・林媽媽（45 歲，臺南）
- **情境**：要安排小孩戶外活動、帶長輩散步或回診，前一晚先看明天的狀況。
- **想知道**：「明天幾點以前出門比較不熱？」「要提醒爸媽帶什麼？」
- **限制**：對數字與分級不熟；習慣把資訊轉傳到 LINE 家族群組。
- **成功標準**：切到「明天」與「兒童・長者」就有具體建議，一鍵複製提醒文字。

### 3. 運動者・小安（26 歲，臺中）
- **情境**：安排跑步、單車或球類練習，平日傍晚、假日清晨。
- **想知道**：「哪個時段 UV 低、體感也不熱？」「今天適不適合中午練？」
- **限制**：會比較逐時數字，也會看其他縣市（週末移地）。
- **成功標準**：逐時時間軸可以選時段，「適合運動」時段直接列出，全台比較可看其他縣市。

### 4. 戶外工作管理者・陳主任（50 歲，高雄，工地或物流）
- **情境**：上班時在辦公室用桌機，排今明兩天的戶外作業與休息。
- **想知道**：「哪幾個小時體感超過 35°？」「有沒有達到高溫資訊門檻？」
- **限制**：需要可信的資料來源與時間，不能拿過期資料排班。
- **成功標準**：看得到資料更新時間與有效期限、高溫門檻提示、資料來源說明，過期時明確不給數值。

## 前 3 項任務

| 優先 | 任務 | 對應介面 | 驗收方式 |
| --- | --- | --- | --- |
| 1 | **5 秒內知道「現在／這個時段能不能出門、要做什麼防護」** | 結論卡標題、風險色帶、兩個指標卡與其行動句 | 手機首屏（390×844）不捲動就看得到標題、UV 與體感數值 |
| 2 | **知道今天或明天「幾點到幾點」要防曬、最熱是幾點** | 全天時段條、需要防曬／已知最高體感／適合運動三格、逐時時間軸 | 時段條與文字時段一致；缺資料時段以斜線標示 |
| 3 | **把提醒傳給家人或同事** | 出門清單＋「複製提醒傳給家人」 | 一鍵複製，複製失敗時提供可長按的文字框 |

次要任務：比較其他縣市（全台地圖與排序清單）、依膚質估算曬紅時間、依對象看建議。

## 非功能需求

| 類別 | 需求 | 本站做法 |
| --- | --- | --- |
| 正確性與誠實 | 缺資料不能當成安全；推估值要標示 | 缺值顯示「資料不足」與斜線；UV 推估標「本站推估」；每個指標附來源與時間 |
| 時效 | 使用者要知道資料多新；過期不能誤導 | 狀態列顯示快照時間、有效期限、最新／延遲；超過 2 小時停止顯示數值 |
| 效能 | 手機 4G 下快速可用 | 單頁靜態站、無第三方地圖底圖、JSON 快照同站載入；Lighthouse 效能目標 ≥ 90 |
| 無障礙 | WCAG 2.1 AA | 文字對比 ≥ 4.5:1；觸控目標 ≥ 44×44 px；色塊皆附文字或數值；鍵盤可操作時間軸與分頁；`aria-live` 播報結論 |
| 可讀性 | 戶外強光、長輩閱讀 | 結論與數字大字級；淺色主題為預設；跟隨系統深淺色 |
| 穩定 | 無版面跳動（CLS < 0.1） | 圖表區預留高度；字型 `display=swap` 並以系統字型為後備 |
| 安全與隱私 | 不暴露金鑰、不追蹤使用者 | 金鑰只在 Actions；瀏覽器只讀同站 JSON；無分析追蹤；偏好只存在 localStorage |
| 可維護 | 設計可延續 | 顏色、間距、圓角、陰影集中在 CSS 變數（design tokens） |

## 裝置評估

- **整體流量**：StatCounter 台灣平台占比，2026 年 6–8 月行動裝置約 52–53%、桌機約 47–48%（含平板時平板約 3%）。來源：<https://gs.statcounter.com/platform-market-share/desktop-mobile-tablet/taiwan>
- **本站情境修正**：上面是全網平均。本站的主要任務是「出門前看一眼」與「轉傳 LINE」，persona 1–3 幾乎都在手機上發生；只有 persona 4 偏桌機。天氣與生活資訊類的使用通常比全網平均更偏行動裝置。
- **推估**：手機約 **70%**、桌機約 **25%**、平板約 5%。這是推估，不是本站實測；本站沒有裝分析工具，若日後要驗證，可用不含個資的 GitHub Pages 流量或隱私友善的計數方式。
- **結論**：**手機為主力裝置**，以 390 px 寬設計首屏，確保結論、時段條與兩個指標在首屏內；桌機（1440 px）作為「排程與比較」情境，善用寬度把結論與指標並排、地圖與清單並排。
