# 使用者與情境

沒有做過訪談；以下是依產品定位與資料特性推論的使用者，上線後應以實際使用狀況修正。

## 使用者

- **通勤上班族**：出門前或午休前在手機上看一眼，想知道中午要不要撐傘、下班時還熱不熱。要在 5–10 秒內得到答案。
- **照顧者**：幫小孩、長輩安排戶外活動，前一晚看明天的狀況，並把提醒轉傳到 LINE 群組。
- **運動的人**：找紫外線低、體感也不熱的時段，週末可能看其他縣市。
- **戶外工作的管理者**：在桌機上排今明兩天的作業與休息，需要知道資料多新、來源是什麼。

## 最重要的三件事

1. 5 秒內知道「現在或這個時段能不能出門、要做什麼防護」。
2. 知道今天或明天「幾點到幾點」要防曬、最熱是幾點。
3. 把提醒複製傳給家人或同事。

## 非功能需求

| 類別 | 做法 |
| --- | --- |
| 誠實 | 缺資料不當成安全；推估值標示為推估；每個指標附來源與時間 |
| 時效 | 結論上方顯示資料時間與年齡，舊資料照常顯示並標示 |
| 效能 | 靜態網站、同站 JSON；Lighthouse 手機與桌面皆為 100 |
| 無障礙 | 文字對比 ≥ 4.5:1、觸控目標 ≥ 44px、鍵盤可操作時間軸與分頁、結論以 `aria-live` 播報 |
| 隱私 | 不追蹤使用者；金鑰只在 Actions 內；偏好只存在瀏覽器 localStorage |

## 裝置

台灣的網站流量約 52–53% 來自手機（[StatCounter](https://gs.statcounter.com/platform-market-share/desktop-mobile-tablet/taiwan)）。這個網站「出門前看一眼、轉傳 LINE」的情境更偏手機，我推估手機約 70%（沒有實測，網站沒有安裝分析工具）。因此以 390px 手機為主設計首屏，桌機（1440px）用來排程與比較。
